# Memory Management

### Address Space

- Set of Location Address of memory that is allocated to
a process is called Address Space

- If these addresses are the actual address on physical
memory, they are called Physical Address Space.

- If this address space is generated by the os and given 
to the program they are called Virtual Address Space.
if v: width of address
then the address space is 0 to 2^v -1

### Why Virtual Address Space

1. Provides Security and Isolation
2. Promotes multiprogramming
3. Large address spaces
4. Ability to run programs larger than available physical memory


- Address space contains
  - stack
  - heap
  - code, text
  - global and static data

### Memory management is done by

1. OS
  - physical memory
2. Each Process
  - their virtual memory
    - stack is automatically by compile code
    - Heap is managed by
      1. allocation
      2. deallocation

- with 32-bit address, one can access 4GB of memory


### Address Space Translation

- Every virtual address is translated to physical address 
by the memory management unit
- For very simple translation we require only two registers
  - register containg base address
  - register containing bound
Generated Physical Address = Base Address + Virtual Address
if Generated Physical Address < Physical Address limit => correct

- This poses significant problem
  - what if not big enough physical memory hole exits
  - what if process needs to grow at runtime
  - it seems wasteful to reserve full address space at 
    the start of the process

### Segmentation

- A process has code, global and static data, heap and stack
- Each of these part can be represented in memory as a seperate
section called segment
- these segments are of different size
now the address has
  1. (segment number, offset)
  2. | Segment no | Base | Limit |
     |---|---:|---:|
     | 0 (Code) | 10000 | 4000 |
     | 1 (Data) | 20000 | 2000 |
     | 2 (Heap) | 30000 | 5000 |
     | 3 (Stack) | 50000 | 3000 |
     Base = physical starting address of the segment
     Limit = size of the segment

     offset >= Limit[2] : segmentation fault

- Drawbacks:
  - Biggest Drawback is
    - Segments are variable-sized.
    - As segments are allocated and freed, holes appear between them.
      - This is called **External Fragmentation**
  - OS needs to maintain a list of free physical memory hole
  - if segment grows too much, need to re-fit the segment in new hole: this is expensive
  - complex: as os need to to maintain segmentation table

### Paging

- The process address space is divided into equally sized
small units called **pages**
- To get rid of external fragmentation, the physical memory
is also divided into equal-sized units called **page frames**
- A virtual page is loaded into a page frame selected at run-
time only when the virtual page is needed. This is called **demand paging**

- **Internal Fregmentation** : wasted space that occurs inside an allocated
memory block when a process is given a fixed-size block larger than it actually needs.

**Page size**, **VPN Virtual Page Number**, **PFN Page Frame Number**, {VPN -> PFN} (Page size)

### Virtual to Physical Page Translation

- Every virtual address is divided into two parts
  - VPN : Virtual Page Number
  - Page offset
- Page offset remain unchanged in translation
- Virtual Page Number is translate to Physical Page Frame Number
- The VPN -> PFN is kept in per-process Page Table

- Steps in Translation
  1. Access the page table
    - every process has Page Table Base Register (PTBR)
      - It is the starting physical address of the Page Table - some offest.
    (suppose the table is has VPN in sequence)
  2. Access the required Page Table Entry (PTE)
    - PTE has 
      +---------------------------------------------------------------------------------------------------+
      | valid bit | present bit | dirty bit | permission bit | mode bit | reference or accessed bit | PFN |
      +---------------------------------------------------------------------------------------------------+

    - valid bit : is PTE valid => has the PTE every created and PFN ever assigned
    -  present bit : is the physical page currently present in memory for PFN
  If the physical page is currently not present in memory for PFN then present bit is 0 which leads to 
  a situation called **Page Fault**
  Page Fault -> handled -> Restart from the same instruction

 - Physical pages are swapped out of memory to swap partition when there is a shortage of pages
 - Page replacement is done using swap daemon or page daemon
 - It keeps the number of free pages between low watermark LWM and high watermark HWM
  3. suppose we now have a present PFN, now offset is added to get the final physical address

- Two memory accesses to get a data item: 
  1. one to get the translation and 
  2. another to get the data

### Caching

- Translation-related memory accesses can be reduced
in number by caching a subset of the translations
used recently inside the processor.
  1. This cache is called **Translation Look-aside Buffer** (TLB),
      one for instruction and one for data
  2. A TLB entry contains a tag (derived from the virtual page number), 
      a PTE, an address space id, a valid bit, repl. bits
  3. A TLB miss leads to a page table access

### Copy on Write

- Demand paging posses a performance problem with fork()
  - all the pages of parent needs to copied to child physical page frame
- This is mitigated by "unless a child or parent do not write to a page after
                        fork(), page is not copied"
  - This policy is called COW copy on write

### LFD

- Longest Forward Distance
- An algorithm that replaces the page with the furthest
access in the future is provably optimal (due to Laszlo
Belady, 1966); also known as the longest forward distance
(LFD) replacement algorithm - cannot be implemented due to dependence on Future

### FIFO

- First In First Out
- Replaces the oldest page provided all the physical page frames are occupied

### LRU

- Least Recently Used
- Replaces the least recently used page
- Two ways of implementing LRU
  1. counter based: **access O(1), victim selection O(N)**
    1. attach a time of access field with each page frame
      - on each access this access field is updated with current hardware tick
      - on page fault the minimum hardware tick is replaced
      - drawbacks
        - need to keep hardware tick size variable
        - on page fault require to run find minimum operation
    2. possible to maintain relative time instead of curren time: **access O(N), victim selection O(N)**
      - on access of page frame its time is reset to zero
      - for all others the time is incremented by 1
      - in case of page fault largest one is replaced.

  2. list based: **access, insertion, and eviction O(1)**
    - HashMap + Doubly Linked List LRU
- Exact LRU requires maintaining and updating the complete recency ordering on every cache access. 
As cache associativity increases, this requires more metadata, hardware logic, power, and complexity. 
Therefore, real CPUs often use cheaper approximations such as Pseudo-LRU that provide similar hit 
rates at much lower hardware cost.

```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

class LRUCache {
private:
    struct Node {
        int key;
        int value;
        Node* prev;
        Node* next;

        Node(int key, int value)
            : key(key), value(value), prev(nullptr), next(nullptr) {}
    };

    int capacity;

    // key -> corresponding node in linked list
    unordered_map<int, Node*> mp;

    // Dummy nodes
    Node* head;  // MRU side
    Node* tail;  // LRU side

    // Insert node immediately after head
    void addToFront(Node* node) {
        node->next = head->next;
        node->prev = head;

        head->next->prev = node;
        head->next = node;
    }

    // Remove node from linked list
    void remove(Node* node) {
        node->prev->next = node->next;
        node->next->prev = node->prev;
    }

public:
    LRUCache(int capacity) : capacity(capacity) {
        head = new Node(-1, -1);
        tail = new Node(-1, -1);

        head->next = tail;
        tail->prev = head;
    }

    int get(int key) {
        auto it = mp.find(key);
        if (it == mp.end()) {
            return -1;  // cache miss
        }
        Node* node = it->second;
        // Move accessed node to MRU position
        remove(node);
        addToFront(node);
        return node->value;
    }

    void put(int key, int value) {
        // Key already exists
        auto it = mp.find(key);
        if (it != mp.end()) {
            Node* node = it->second;
            node->value = value;
            // This key was just used -> make it MRU
            remove(node);
            addToFront(node);
            return;
        }
        // Create new node
        Node* node = new Node(key, value);
        mp[key] = node;
        addToFront(node);
        // Cache exceeded capacity
        if (mp.size() > capacity) {
            // tail->prev is the LRU node
            Node* lru = tail->prev;
            remove(lru);
            mp.erase(lru->key);
            delete lru;
        }
    }

    ~LRUCache() {
        Node* curr = head;

        while (curr != nullptr) {
            Node* next = curr->next;
            delete curr;
            curr = next;
        }
    }
};
```

### LFU Least Frequently Used

- Evicts the item with the lowest total access count

```cpp
#include <bits/stdc++.h>
using namespace std;

class LFUCache {
private:
    struct Node {
        int key;
        int value;
        int freq;

        Node(int key, int value)
            : key(key), value(value), freq(1) {}
    };

    using List = list<Node>;

    int capacity;
    int minFreq = 0;

    // key -> iterator to its node
    unordered_map<int, List::iterator> cacheMap;

    // frequency -> nodes
    // Front = MRU, Back = LRU
    unordered_map<int, List> freqMap;

    void updateFreq(int key) {
        auto nodeIt = cacheMap[key];
        int oldFreq = nodeIt->freq;

        Node node = *nodeIt;

        // Remove from old frequency list
        freqMap[oldFreq].erase(nodeIt);

        // If minimum-frequency list became empty,
        // the node moves from f to f+1.
        if (freqMap[oldFreq].empty()) {
            freqMap.erase(oldFreq);

            if (minFreq == oldFreq)
                minFreq++;
        }

        // Increase frequency and insert at front
        node.freq++;
        freqMap[node.freq].push_front(node);

        // Store new iterator
        cacheMap[key] = freqMap[node.freq].begin();
    }

public:
    explicit LFUCache(int capacity)
        : capacity(capacity) {}

    int get(int key) {
        auto it = cacheMap.find(key);

        if (it == cacheMap.end())
            return -1;

        int value = it->second->value;
        updateFreq(key);

        return value;
    }

    void put(int key, int value) {
        if (capacity == 0)
            return;

        // Existing key
        auto it = cacheMap.find(key);

        if (it != cacheMap.end()) {
            it->second->value = value;
            updateFreq(key);
            return;
        }

        // Evict LFU; among ties, evict LRU
        if (cacheMap.size() == capacity) {
            auto &list = freqMap[minFreq];

            auto victim = prev(list.end());
            int victimKey = victim->key;

            cacheMap.erase(victimKey);
            list.erase(victim);

            if (list.empty())
                freqMap.erase(minFreq);
        }

        // New entries always have frequency 1
        freqMap[1].push_front(Node(key, value));
        cacheMap[key] = freqMap[1].begin();

        minFreq = 1;
    }
};
```

### Reference Bit Algorithm

- The reference-bit algorithm approximates LRU by associating a reference bit with each page. 
Hardware sets the bit when the page is accessed, and the OS periodically clears it. 
Pages whose reference bit remains 0 have not been used during the interval and are preferred for replacement.

### Second Chance Algorithm

- Second Chance = FIFO + Reference Bit.
FIFO determines which page to examine first, while the reference bit 
determines whether that page deserves another chance
- When we need to evict but the reference bit is set for the element 
at the front of the queue, its reference bit is reset and moved at the end
of the queue giving a second chance

                  FIFO
                    ↓ + Reference Bit
                  Second Chance
                    ↓ circular implementation
                  Clock Algorithm

### Pseudo-LRU PLRU

- Pseudo-LRU approximates LRU using a small amount of hardware state instead of maintaining the exact ordering
of all cache ways. A common implementation is tree-based PLRU, where N-way associativity uses N−1 bits. On every
access, bits along the path are updated, and on eviction the tree is traversed to select an approximately
least-recently-used way.

```cpp
#include <iostream>
#include <vector>
using namespace std;

class PLRU {
private:
    int ways;
    vector<bool> tree;

public:
    PLRU(int ways) : ways(ways), tree(ways - 1, false) {}

    // Called whenever a particular way is accessed
    void access(int way) {
        int node = 0;
        int left = 0;
        int right = ways - 1;

        while (right - left > 1) {
            int mid = (left + right) / 2;

            if (way < mid) {
                // Access went LEFT.
                // Mark RIGHT as the LRU direction.
                tree[node] = true;

                node = 2 * node + 1;
                right = mid;
            } else {
                // Access went RIGHT.
                // Mark LEFT as the LRU direction.
                tree[node] = false;

                node = 2 * node + 2;
                left = mid;
            }
        }
    }

    // Return approximately LRU way
    int getVictim() const {
        int node = 0;
        int left = 0;
        int right = ways - 1;

        while (right - left > 1) {
            int mid = (left + right) / 2;

            if (tree[node] == false) {
                // LEFT subtree is LRU
                node = 2 * node + 1;
                right = mid;
            } else {
                // RIGHT subtree is LRU
                node = 2 * node + 2;
                left = mid;
            }
        }

        return left;
    }
};

int main() {
    PLRU plru(64);

    plru.access(10);
    plru.access(35);
    plru.access(60);
    plru.access(7);

    cout << "Victim way = "
         << plru.getVictim()
         << '\n';
}
```

### Thrashing

- A process is said to be thrashing if it is suffering from
an excessive volume of page faults
- Happens if the process fails to get enough page frames to
accommodate its working set
- Thrashing avoidance is 2 step process
  1. Working set estimation
    - This is done using reference bit
  2. Pre-paging
    - The working set list of a process is stored along with
      its context and the OS swaps in these pages before
      scheduling the process
      - This is called pre-paging or prefetching
      - Downside: The working set list may not be accurate and
        some of the swapped in pages may not be used
